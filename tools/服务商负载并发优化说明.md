## Qwen 生图与编辑 API

所有请求带 `Authorization: Bearer <API_KEY>`。密钥由服务管理员提供，应通过单独的安全渠道交付给服务商；本文不包含密钥。公网入口核对时返回 401（缺少 Bearer 密钥），表示网关可达且鉴权已启用。

### 提交任务

`POST /v1/tasks`，`multipart/form-data`，返回 HTTP 202 和任务 ID。

| 字段 | 类型/规则 | 说明 |
|---|---|---|
| `model` | 字符串，固定 `qwen` | 模型标识 |
| `operation` | `text_to_image` 或 `image_edit` | 文生图或参考图编辑 |
| `prompt` | 必填字符串 | 生成描述或编辑指令 |
| `image` | 单个文件，可选 | 兼容旧客户端的单图编辑字段 |
| `images` | 可重复文件字段，最多 10 张 | 多图编辑，按上传顺序使用；不可与 `image` 同时提交 |
| `width`, `height` | 可选整数，必须同时填写 | 默认 2048×2048；每边 256–4096、32 的倍数，总像素不超过 4,200,000 |
| `seed` | 可选非负整数 | 范围 0 至 2^63−1；省略时随机生成，查询任务时可见实际值 |
| `steps` | 整数，默认 40 | 范围 1–100 |
| `transparent` | 布尔值，默认 `false` | `true` 时要求模型生成透明效果，输出 PNG 保留 Alpha（实际透明度受模型输出影响） |
| `idempotency_key` | 可选字符串，最长 128 字符 | 相同 API key 下重复提交会返回原任务 |

图片仅接受 PNG/JPEG/WebP；单张上传不超过 10 MiB，解码后不超过 1600 万像素。`image_edit` 必须带 1–10 张图片；`text_to_image` 不带图片。结果为 PNG。

最简文生图示例：

```bash
curl -X POST 'http://60.171.65.125:30141/v1/tasks' \
  -H "Authorization: Bearer ${IMAGE_API_KEY}" \
  -F 'model=qwen' -F 'operation=text_to_image' \
  -F 'prompt=一只坐在窗边的橘猫' -F 'steps=40'
```

编辑示例（重复 `images` 字段即可上传多张）：

```bash
curl -X POST 'http://60.171.65.125:30141/v1/tasks' \
  -H "Authorization: Bearer ${IMAGE_API_KEY}" \
  -F 'model=qwen' -F 'operation=image_edit' \
  -F 'prompt=将主体放入第二张图的室内场景，保持主体外观' \
  -F 'images=@subject.png' -F 'images=@room.png' -F 'seed=42'
```

### 查询和下载

- `GET /v1/tasks/{task_id}`：查询 `queued`、`running`、`succeeded` 或 `failed` 状态；返回 `result_url` 和 `parameters`。
- `GET /v1/tasks/{task_id}/result`：任务成功后下载 PNG。
- 两个接口都需要相同的 Bearer 鉴权。
- 提交成功返回体示例：`{"id":"<uuid>","status":"queued","status_url":"/v1/tasks/<uuid>"}`。
- 队列满返回 429；没有健康 worker 或维护时返回 503。部分 worker 故障时其他健康副本继续提供服务。

## TRELLIS.2 图片转 3D API

当前服务为 `web_v2` 自定义 HTTP/JSON 接口，不是 OpenAI 风格接口，也没有 FastAPI OpenAPI 页面。当前实现没有应用层 Bearer 鉴权；如果供外部服务商压测，应通过网络 ACL、代理或临时测试入口控制访问。

### 提交任务

`POST /generate`，`Content-Type: application/json`，返回 HTTP 202。输入图像以 Base64 放在 JSON 中。

| JSON 字段 | 类型/默认值 | 说明 |
|---|---|---|
| `image_base64` | 必填字符串 | 原始图像文件的 Base64 编码 |
| `image_name` | 字符串，默认 `input.png` | 输入文件名 |
| `glb_name` | 字符串，默认 `sample` | 输出 GLB 名称；服务端补 `.glb` |
| `latent_res` | `512`、`1024` 或 `1536`，默认 `1024` | 推理分辨率档位；`1536` 使用 cascade 路径 |
| `seed` | 非负整数，默认 `42` | 随机种子，最大 2^31−1 |
| `decimation_target` | 正整数，可选；服务默认 1,000,000 | 输出网格简化目标 |

当前进程 JSON 请求体上限为 32 MiB（Base64 内容也计入），服务不接收 `image_path`/`save_path` 本地路径字段，视频输出关闭。接口只做单张图像到 3D 的任务提交，不接收文字 prompt。

示例：

```bash
python client.py \
  --server http://60.171.65.125:30056 \
  --image ./input.png --output-dir ./trellis-output \
  --latent-res 1024 --seed 42 --glb-name asset
```

服务仓库内置客户端位置：`/root/userdata/300workspace/web_service/TRELLIS.2/web_v2/client.py`。

### 查询和下载

- `GET /health`：服务就绪状态、GPU、队列、worker 状态和显存数据。
- `GET /jobs/{job_id}`：查询任务；状态为 `queued`、`running`、`succeeded` 或 `failed`，包含阶段事件、分配 GPU、耗时和 artifact 信息。
- `GET /files/{job_id}/{filename}`：下载输出文件。
- 成功时主要产物是 GLB，响应中提供 `artifacts.glb.url` / `glb_url`。提交/查询 JSON 都带 `job_id`；轮询直到 `status=succeeded` 后下载。
- 队列满时返回 429。现配置队列容量不设上限，服务商压测时需要关注排队时延和积压增长。

## 建议服务商重点测量

1. 分别按 Qwen 文生图、单图编辑、多图编辑（1/2/5/10 张）和 TRELLIS 三档 `latent_res` 建立压测组；报告并发 1、2、4、逐步增加的吞吐、P50/P95/P99 延迟、失败率、排队时长和每卡显存峰值。
2. 记录排队和推理时长的拆分、各 GPU 利用率/显存、CUDA OOM、CPU 内存及 CPU offload 次数；Qwen 与 TRELLIS 共用 H100 主机资源，GPU 2 还有独立作业占用，压测前需固定资源基线。
3. 先测单服务，再测 Qwen/TRELLIS 混合请求；确认限流、队列上限、超时和背压策略，重点检查 TRELLIS 当前无界等待队列在突发流量下的积压行为。
4. 报告峰值并发下是否出现 OOM 或明显长尾；不要仅以 HTTP 202 接受速度作为推理吞吐，需等到任务完成并验证输出文件。
