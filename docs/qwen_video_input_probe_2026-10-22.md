# Qwen 视频输入能力实测

测试日期：2026-10-22  \n+接口：`https://models.sjtu.edu.cn/api/v1/chat/completions`  \n+请求模型：`qwen`（响应中的 `model` 也是 `qwen`，不能据此确认它就是 `qwen3.8-27b`）

## 结论

- 接口接受 OpenAI-compatible `video_url`，本地 MP4 可用 data URI 发送。
- 视频视觉理解可用；对持续约 2 秒的颜色、OCR 文本和先后顺序识别准确。
- 视频内音轨不可用。纯黑画面保留真实 AAC 对话音轨时，模型返回 `AUDIO_NOT_AVAILABLE`。
- 后端会对视频稀疏抽帧。24 秒视频中持续 0.2 秒的黄色事件完全漏检，持续 1–2 秒的首尾文字能够识别。
- 时间定位粒度较粗。实际 21–23 秒的事件被回答为 21–22 秒，不能用作帧级或精确动作边界。
- 真实视频概括可用，但存在动作幻觉和镜头判断错误。模型正确识别一男一女、室内场景和人物移动，却虚构了递交物品，并遗漏从全景到双人中景的画面变化。
- 延迟存在严重长尾。原始 720p/30fps/带音频的 8 秒视频在 300 秒超时；压缩为 640x360/8fps/无音频后有一次 3.346 秒成功，但另两个更小的变体仍在约 180 秒超时。因此文件越小不保证越快，必须重试和回退。

## 实测结果

| 用例 | 输入 | 结果 | 延迟 |
|---|---|---|---:|
| 真实片段原文件 | 8 秒，1280x720，30fps，含 AAC，1.7MB | 超时 | 300.378s |
| 黑屏但保留真实对话 | 8 秒，140KB | 明确无法访问音轨 | 2.759s |
| 三段颜色与 OCR | 6 秒，红/绿/蓝各 2 秒 | 颜色、文字、顺序、时间全部正确 | 22.039s |
| 长视频稀疏事件 | 24 秒，含 0.2 秒闪现 | 看见首尾事件，漏掉 0.2 秒事件 | 27.368s |
| 压缩真实片段 | 8 秒，640x360，8fps，无音频，294KB | 成功，但有语义幻觉 | 3.346s |
| 更低清真实片段 | 8 秒，320x180，4fps，无音频，75KB | 超时 | 180.242s |
| 缩短真实片段 | 4 秒，640x360，8fps，无音频，161KB | 超时 | 182.817s |

不同长度视频的 prompt token 数都约为 3.7K（6 秒 3688、8 秒 3693、24 秒 3712），进一步表明服务端采用了接近固定预算的抽帧/视觉编码，而不是逐帧读取。

## 对 StageRecon 的建议

1. 生产管线不要把原始视频直接交给 Qwen。由我们自己按镜头抽帧，并把帧时间戳显式写入提示词。
2. 基础采样使用每秒 1–2 帧；切镜、快速运动、遮挡、嘴部活动和人物交互窗口提升到 6–12 fps。
3. 音频必须独立走 ASR/说话人流程，再将带时间戳的台词和 Person ID 作为文本上下文交给 Qwen。
4. Qwen 负责 `Reference + Shot + Motion + Global` 的视觉语义草稿，不负责几何真值、精确动作边界或音频转录。
5. 请求设置超时和回退：建议单次 60–90 秒、最多重试 2 次；失败后自动回退到多图片输入。
6. 短暂动作不能只依赖均匀抽帧。先用镜头变化、光流、目标轨迹或 Blender 已知时间段发现候选窗口，再密集采样。
7. 所有模型输出保留 `evidence_frames`、`confidence` 和 `timing_precision`，将模型给出的秒数标记为估计值。
